# Git Hooks — 讓檢查器在**最便宜的時刻**叫

**Purpose**: commit / push 前的本機自動檢查。
**Created**: 2026-08-07
**Last Modified**: 2026-08-07
**Status**: Active

---

## 啟用（一次性，每個 clone 都要各自做）

```bash
git config core.hooksPath scripts/hooks
```

停用：`git config --unset core.hooksPath`

### ⚠️ 啟用前提：先確認那些指令真的跑得通

**不要在專案骨架剛建好、還沒有任何原始碼的時候啟用。**
這時 profile 填進來的 `LINT_CMD` 指向的目錄可能還不存在，
一啟用就是**第一次 commit 就被擋** —— 而那正是下面第 2 條講的死法。

啟用檢查清單：

- [ ] `LINT_CMD` 在本機跑得過（不是「應該可以」，是真的跑一次）
- [ ] `TEST_CMD` 在本機跑得過
- [ ] `python scripts/lint/run_all.py` 綠

三項都過再啟用。任一項不過，先修那個，不要先啟用 hook。

> **為什麼用 `core.hooksPath` 而不是 `.git/hooks/`**：`.git/` 不進版本控制，
> 放在那裡的 hook 每個人都要自己手動裝、改了也沒人知道。
> `scripts/hooks/` 是**受版本控制的**，改動走 PR、新人一行指令就啟用。

## Hooks

| Hook | 觸發 | 做什麼 | 緊急跳過 |
|---|---|---|---|
| `pre-commit` | `git commit` | ① 架構 lint（`run_all.py`，秒級）② 專案 lint | `--no-verify` |
| `pre-push` | `git push` | 測試全套 | `--no-verify` |

## 為什麼需要這個（CI 不是已經有了嗎）

CI 確實會跑同一批檢查。差別在**什麼時候叫**。

這套模板的核心信條是「**規則要有東西會叫，才算規則**」。但那句話還有下半段：

> **叫得太遲，跟不叫的差別沒有想像中大。**

一個在 CI 才被攔下來的問題，代價是：推上去 → 等 CI → 紅 → 切回來 → 修 →
再推 → 再等。而同一個問題在 `git commit` 當下被攔，代價是**十秒鐘**。

架構 lint（規則檔膨脹 / 斷鏈 / 路徑失效 / 假 pending）特別適合放在這裡 ——
它們全部是秒級、全部是本機就能判定、而且全部是「當下修最便宜」的問題。

## 設計原則（違反這幾條，hook 會被繞過然後永遠被繞過）

### 1. pre-commit 只放秒級的東西

會讓人等的 pre-commit 一定會被 `--no-verify`。一旦養成習慣，
之後**所有**檢查一起失效 —— 包括那些本來很快、本來會抓到東西的。

慢的東西（測試、建置、E2E）放 pre-push；更慢的放 CI。

### 2. ⭐ 不要讓 hook 在第一天就攔死所有人

**這是最容易犯、後果最大的一條。**

典型踩法：把 `format --check` 加進 pre-commit，而既有 codebase 的格式從未統一過。
結果是**改任何一個檔都被攔** —— 連改一行註解都不行。
所有人立刻學會 `--no-verify`，然後這個習慣**再也回不去**。

正確順序：

1. 先全庫跑一次格式化（`<format 指令>`），單獨一個 commit
2. 確認全庫乾淨
3. **然後**才把 `format --check` 加進 pre-commit

同樣的邏輯適用於任何「全庫都會紅」的檢查：型別檢查、覆蓋率門檻、新的 lint 規則。
**先清零，再設閘。** 順序反了就等於沒設。

> 這也是本模板的 `pre-commit` 預設**不含** format check 的原因 ——
> 它不知道你的 codebase 現在乾不乾淨。清零之後自己加。

### 3. `--no-verify` 要留著，但要知道自己在幹嘛

逃生門必須存在（半夜修 production 不該被 lint 擋）。
但**習慣性跳過**跟沒有 hook 是同一件事，而且更糟 ——
因為你會以為自己有防護。

判準：**你能講出這次為什麼要跳過嗎？** 講不出來就不要跳。

## 加新檢查時

問一句：**這個檢查失敗時，人要多久才能修好？**

| 修復成本 | 放哪 |
|---|---|
| 秒級、本機可判定 | `pre-commit` |
| 分鐘級、本機可判定 | `pre-push` |
| 需要乾淨環境 / 外部服務 / 矩陣 | CI |

還有一個前置問題：**現在全庫過得了嗎？** 過不了就先做第 2 條的清零步驟。
