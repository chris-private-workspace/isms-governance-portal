# 永不刪除 checklist 上未勾選的項目

**規則**：phase checklist 上的項目，**只能** `[ ]` → `[x]`。
**永遠不要**刪除還沒完成的 `[ ]` 項。

## 為什麼

Checklist 是**真相表**。它唯一能回答的問題是：

> 「當初計畫了什麼 vs 實際出貨了什麼？」

刪掉未完成的項目 = **銷毀證據**。retrospective 時你會看到一份「全部完成」的 checklist，
而完全不知道有東西被砍掉了。

## 真實案例

某個 phase 在範圍縮減時，把未完成的 `[ ]` 項直接刪掉，讓 checklist 看起來全綠。
結果：

- retrospective 無法診斷為什麼估算失準（因為「計畫的量」被事後改小了）
- 被砍掉的功能沒有進入 carryover 清單，**直接消失**
- 下一個 phase 的估算基於錯誤的歷史資料

## 正確做法

| 情況 | 做法 |
|------|------|
| 完成了 | `[ ]` → `[x]` |
| 被擋住了 | 保留 `[ ]`，下面加 `🚧 阻塞: <原因>` |
| 範圍縮減，這次不做了 | **保留 `[ ]`**，在 progress.md 註明原因 + 加到 `docs/01-planning/BACKLOG.md` |
| 發現這項根本不需要 | **保留 `[ ]`**，標註「取消：<理由>」 |

**任何情況下都保留那一行。** 一個 `[ ]` 的成本是一行文字；
一個被刪掉的 `[ ]` 的成本是整個 phase 的可追溯性。

## 同樣的原則適用於

- **文件** —— 未授權不刪
- **測試** —— 不刪測試 / 不關測試 / 不跳測試（壞了就修）
- **待辦清單** —— 完成了要標記完成，不是刪掉（移到 §Shipped Pointer Index）

## 例外

唯一可以刪的情況：**這一項從一開始就寫錯了**（例如複製貼上的殘留、
明顯的重複項）。這種情況要在 progress.md 註明「刪除誤植項：<內容>」。
