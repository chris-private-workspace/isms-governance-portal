# 證據要真的支持結論

**規則**：把工具輸出變成結論之前，先問一句 —— **這份輸出真的支持我要寫的那句話嗎？**

這條**不是**「不要捏造工具結果」（那是 [[feedback_never_fabricate_tool_results]]）。
這裡的工具輸出全部是真的，**推論是錯的** —— 所以它更難自己察覺，
也更容易通過 review：讀的人看到有 grep、有數字，就當已經查過了。

## 七種形態（全部都真實發生過）

| # | 形態 | 長什麼樣 | 為什麼錯 |
|---|---|---|---|
| 1 | **命中數當證據** | 用一條混合 pattern 的命中數，推論「SQL 全部參數化」 | 命中數只證明「有東西匹配」，不證明**匹配到的是對的東西**。非零命中要**逐處讀** |
| 2 | **檔名當內容** | 看到 `backup.yml` 就結論「有備份機制」 | 檔名是標籤，不是實作。要讀內容 |
| 3 | **單一檔當全樹** | 只讀一個 `main` 設定檔就判「某項未做」；實際做在被 include 的另一個檔裡 | 分層 / include 的設定必須追到底 |
| 4 | **由類別推論內容** | 「這是 trace endpoint」→「所以它含使用者輸入」 | 沒讀 schema 就從名字推語義。同一輪犯了兩次 |
| 5 | **零命中但搜錯範圍** | 「零個前端呼叫者」—— 但那個 URL 是後端合成的，**原則上就不會出現在前端原始碼** | 零命中要先證明**搜對了地方**才有意義 |
| 6 | **撞上限當搜完** | grep 回傳被截斷（`head_limit` / 上限）就當全貌 | 撞上限 = **還沒搜完**。縮小範圍分批，或換工具 |
| 7 | **分組完不對總數** | 分類統計加起來 ≠ 母體 | 分組完一定要對總數，差額就是漏掉的那批 |

## 操作守則

- **零命中**：先反問「這個東西如果存在，會長什麼樣、會在哪？」搜對地方再下結論
- **非零命中**：逐處讀。**數字本身不是證據**
- **找受影響的檔**：用 import / 引用關係搜，或**直接跑全套**；
  **不要用檔名 glob 猜**（命名慣例永遠有例外）
- **能交給工具窮舉的，不要人手抽樣** —— 人手抽樣的覆蓋率沒有人知道，包括你自己
- **交付物要自帶覆蓋聲明**：「掃了什麼範圍 / 用什麼方法 / 什麼沒掃到」。
  一份沒有覆蓋聲明的稽核報告，讀的人只能重做一次

## 為什麼要寫成記憶

因為這是**同一個病反覆發作**，而不是偶發失誤。共通結構是：

> **拿一個容易取得的代理指標（數量 / 檔名 / 類別 / 目錄結構），
> 去回答一個需要讀內容才能回答的問題。**

代理指標之所以誘人，正是因為它便宜。**問題越大，越想用代理指標** ——
而那正是它最不可靠的時候。
