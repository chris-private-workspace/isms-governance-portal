## 6. 踩到的坑

1. **⛔⭐ Prisma 的 enum 有三份真相，而中間那份會擋。**
   `schema.prisma` · **generated client** · DB catalog。我預測「移除 schema 的 enum 值後 int 全綠
   （DB 的 enum 由已套用的 migration 建立）」—— **錯了**，generated client 在 **runtime 也驗證**。
   ⇒ **`ALTER TYPE … ADD VALUE` 的 migration 必須配 `prisma generate`**，否則會出現
   「**DB 接受、應用層拒絕**」的分歧，而那**只在部署時現形**：本機 int 的 global setup 每次重建 DB
   又重新產生 client，所以開發迴圈**結構上看不見它**。→ `AD-PrismaEnumThreeTruths-1`

2. **⛔⭐ 用便宜的字串操作做需要理解結構的工作 —— 我同一天犯了兩次。**
   (a) seed id `ab0/ab1` → `ac0/ac1` 用**全檔 replace**，而 `ab0` 在 `int-global-setup.js`
   **出現兩次**（另一次是 `assessment_instances`）⇒ `assessment.int.spec.ts` **7 個測試紅**；
   (b) `t.index('  ],')` 找陣列結尾，匹配到**第一筆資料的** `    ],` ⇒ 切出語法錯誤的檔案。
   ⚠️ **兩次都不是我發現的** —— 一次是 int suite 報紅，一次是 node 拒絕載入。
   修法都是**錨定結構邊界**（唯一 ref code / 含換行的完整界定符）**+ `assert` 計數符合預期**。
   → `AD-TextEditStructuralScope-1`

3. **⛔ 中性化的順序不可顛倒，那是驗收價值的唯一來源。**
   要證明 W13 的漂移守衛是真的，必須**先建表 + repository、不碰 `AUDITED_MODELS`、再跑**。
   得到「恰好 1 紅、訊息自己指名、15 條覆蓋測試一條未動」。
   **先改再跑得到的是綠色，而綠色不能區分「守衛有效」與「守衛從不看新表」。**

4. **⚠️ `tail -N` 會吃掉證據（不只吃掉退出碼）。**
   我的 gate script 用 `tail -25`，把 jest coverage 的 `All files` 摘要行切掉了
   （那一行在表格**最前面**）。判定沒錯 —— 退出碼取自 `PIPESTATUS[0]` 而非 `tail` ——
   但**數字得重跑一次才拿到**。⇒ `AD-GrepAssertion-1` 的鄰居。

5. **⚠️ Grep 回報的是「行數」不是「出現次數」。**
   post-merge 重指腳本帶 `assert total == 17`（取自 Grep 輸出），實際替換 **27** 處。
   **腳本對、我的預期值錯** —— `| 7bea684 → 652fb64 |` 是一行兩個 SHA。
   ⭐ 那個 assert 是坑 2 當天才提議的修法，**當天就攔下一次真實錯誤** ——
   只是它保護的不是操作（操作完全正確），是**我對操作的理解**。

6. **⛔ 本 repo 的 PR 一律 rebase merge，SHA 每次全被改寫（W14 連中兩次，累計第 6、7 次）。**
   最要緊的是那些**價值就是可查證性**的引用（如「預測寫在執行之前」的 commit）——
   改寫後它指向 main 上不存在的物件，**而所有 gate 仍然全綠**。
   ⭐ **穩定錨點是 author date 不是 SHA**：已第 5 次確認 rebase **逐秒不變**（含 subject），
   而 W14 的 calibration 完全由 author date 導出 ⇒ **數字撐過了 rebase，即使 SHA 沒有**。

7. **⛔ `git branch -d` 的結果（拒絕或放行）都不構成證據。**
   W13 它拒絕；W14 它**放行**了 —— 因為 GitHub 在 merge 當下刪了遠端分支而本機 tracking ref
   **尚未 prune**，於是 `-d` 拿分支比對**它自己的陳舊副本**，訊息自己說了
   `but not yet merged to HEAD`。**那個安全檢查在當下是恆真的。**
   ⇒ 唯一權威是 `git cherry origin/main <branch>` 的 `+` 數 = 0，
   且**刪除前先 `git remote prune origin`**。（交接前已做對照實驗證實，見 §2a-2。）

8. **⚠️ `lint:negative` 是 root script。** 加 `-w apps/api` 會得到 `Missing script`。
