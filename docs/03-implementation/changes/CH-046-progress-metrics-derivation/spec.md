# CH-046 — 五把尺，機械導出：讓「進度到哪了」有一個統一且不會過期的答案

**Status**: 已完成（使用者 2026-08-20 核准 —— 含「**不輸出整體百分比**」的裁決）

## Problem

「M0–M9 完成多少」這個問題，今天**每次被問都要重新臨時算一遍**，而臨時算出來的數字會錯。

**本次對話就錯了一個**：我報「前端接線 **2 / 29** 頁」，實測是 **3 / 29**
（漏掉 `/risks/[id]`，W22 垂直切片接的）。錯因不是粗心 —— 是我**憑對 phase 的記憶數**，
沒有量。這是本專案第 **6** 個被發現的手寫計數器
（前五：實體數 `AD-12` · 稽核表數 `AD-18`/`AD-23` · ROADMAP P0 數 · §Open 總數 · 稽核模型數 `AD-61`）。

更根本的問題是**單一百分比會誤導**。同一個專案用五把尺量出來的數字是：

| 尺 | 值 |
|---|---|
| 里程碑計數 | 33–50% |
| 資料模型 | 34 / 36 = **94%** |
| 稽核覆蓋 | 16 / 34 = **47%** |
| 前端接上領域資料 | 3 / 29 = **10%** |
| 八個範疇有實作 | **5 / 8**（`identity` 0 · `workflow` 0）|

**94% 與 10% 描述的是同一個 repo 的同一天。** 任何一個單一數字都會讓讀的人得到錯的印象。

---

## Root Cause

⭐ **不是「沒人做過這個工具」。是這些數字沒有一個共同的家。**

- `check_entity_index.py` 已經導出 **34 / 36**，但那個數字只在 `run_all` 的一行輸出裡閃過
- `AUDITED_MODELS` 是 code 裡的真相（`audit.module.ts:82`），沒有任何文件機械地引用它
- 「前端接線幾頁」從未被任何東西量過 —— 它每次都是人數的
- `07-wave1-build-plan.md:31-42` 的 M0–M9 是**規劃**，它不知道自己實現了多少

⇒ 於是每次盤點都重算，而重算的東西**每次都有機會算錯，且錯了沒有人會發現**。

⛔ 這個洞的形狀早被寫在紙上 —— `check_backlog_counts.py:17-19`：

> 「這個 detector **自己不持有任何期望值**；把一個期望值接進去，
> 只是把手寫的計數器搬進 Python。」

那份檔案解決的是同一個病（手抄計數），**而它的解法沒有被套用到第二個場合** ——
那正是本次審計 `AD-65` 記下的教訓。本片是那條教訓的第一個實作。

## Solution

### 範圍決策

| 決策 | 選擇 | 為什麼不是另一個 |
|---|---|---|
| 工具形態 | **detector + living 文件，兩邊比對** | 純報表腳本（只印數字）**沒有東西保證文件是新的** —— 而使用者的需求是「回看進度時統一地查看」，看的是文件。文件必須被強制為真 |
| 期望值住哪 | **文件裡宣告，detector 只導出與比對** | detector 內建期望值 = 把手寫計數器搬進 Python（`check_backlog_counts.py:17-19` 的原話）|
| 里程碑 🟢/🟡/🔴 | ⛔ **工具不判定，只驗證它的前提** | 見下方 §關鍵設計細節 1 —— 這是本片最容易做錯的地方 |
| 百分比 | ⛔ **不輸出任何單一百分比** | 見 §關鍵設計細節 3 |

### 逐項變更

| 檔案 | 類型 | 說明 |
|---|---|---|
| `docs/01-planning/PROGRESS-METRICS.md` | **新增** | living 文件。五把尺的**宣告值** + M0–M9 里程碑判定表（人寫）+ 每個里程碑的**機器可驗錨點** |
| `scripts/lint/check_progress_metrics.py` | **新增** | 導出五把尺 + 驗證里程碑錨點 + 與文件宣告比對，不符即 fail。含無條件 self-test（兩個方向）|
| `scripts/lint/tests/test_progress_metrics.py` | **新增** | 單元測試，含**負面測試**：改掉宣告值必須轉紅並指名哪一把尺 |
| `scripts/lint/run_all.py` | 修改 | 註冊 `progress-metrics`（**10 → 11**）|
| `docs/01-planning/README.md` | 修改 | 索引加 1 行 |

### 五把尺的導出方式（全部實測過，非設計意圖）

| # | 尺 | 導出方式 | 2026-08-20 實測 |
|---|---|---|---|
| 1 | **資料模型** | 引用 `check_entity_index.py` 的既有邏輯，**不重寫** | 34 / 36 |
| 2 | **稽核覆蓋** | `AUDITED_MODELS` set 大小（`audit.module.ts:82`）vs 已建實體數 | 16 / 34 |

| 5 | **手寫產品碼** | 行數，**排除 `src/generated/`** | api ≈ 8k prod / 14.7k test |

### ⭐ 關鍵設計細節（拿掉就會壞）

**1. ⛔ 里程碑判定是人的，錨點是機器的 —— 這是本片的核心。**

M0–M9 的 🟢/🟡/🔴 **不可以由工具算**。「M6 算不算完成」取決於詳情頁要不要算、
attestation 要不要算 —— 那是判斷，寫進 Python 就是把判斷偽裝成量測（AP-3）。

改成：**每個里程碑在文件裡帶一個機器可驗的錨點**，detector 只驗錨點還成不成立。

```
| M4 | 🔴 未開始 | anchor: scope_ts_count('identity') == 0 |
| M5 | 🔴 未開始 | anchor: scope_ts_count('workflow') == 0 |
| M3 | 🟡 部分   | anchor: audited_models() == 16 |
```

有人往 `identity/` 加了第一個檔 ⇒ 錨點破 ⇒ **紅燈，強制重新判定 M4**。
⇒ 工具不宣稱「M4 未開始」，它宣稱的是「**你當初據以判定的那件事還成不成立**」。

**2. ⛔ 「接線」有兩個合理定義，數字不同，所以定義要印在輸出裡。**

實測（`grep -rln` 兩個方向都跑過）：

| 類別 | 頁數 | 是誰 |
|---|---|---|
| 接上**領域** API（`@/lib/api/*`）| **3** | `/policies` · `/risks` · `/risks/[id]` |
| 其他 HTTP（非領域資料）| **2** | `app/page.tsx` → `/health` · `login/page.tsx` → `/api/demo-session` |
| 純 fixture / 靜態 | **24** | W19 port 進來的其餘畫面 |

⇒ 「接線幾頁」的答案可以是 **3** 也可以是 **5**，看你問的是哪一個。
**工具輸出三個數字與定義，不輸出一個。**
判準與 `AD-LocalGateSetIncomplete-1` 同形：**「gate 全綠」要自帶射程，指標也一樣。**

**3. ⛔ 不輸出任何單一百分比。**

這條是刻意的，而且理由就在本片的緣起：使用者問「是不是只有 50%」，
而誠實的回答需要**五把尺 + 一個框架修正**（M0–M9 只是 Wave 1）。
一個印出「進度 47%」的工具會把這場對話重新製造一次。

⚠️ **例外**：各把尺自己的分數（`34 / 36`）**照印** —— 那是有分母、有定義的比值，
與「整體完成度 X%」不是同一種東西。

**4. 五把尺全部是代理指標，輸出必須自帶這句話。**

行數不是完成度，檔數不是功能。`AD-ProxyMetricAsAnswer-1` 是本專案的 🔴 P0 家族。
⇒ detector 的輸出結尾固定印一行射程聲明，**不可移除**（測試會斷言它在）。

### 明確不做的

- ❌ **不算整體完成度百分比**（§關鍵設計細節 3）
- ❌ **不涵蓋 Wave 2 / Wave 3** —— 分母是 Wave 1（`07-wave1-build-plan.md`）。文件標題與輸出都要寫明
- ❌ **不重寫 `check_entity_index` 的實體計數** —— 引用它，不複製（AP-2）
- ❌ **不做趨勢圖 / 歷史序列** —— YAGNI（AP-5）。要看歷史去 `git log` 這份文件
- ❌ **不改任何產品碼**

## Impact

- **Breaking change**: no · **Migration**: no · **Config**: 無 · **重啟需求**: 無
- **Rollback**: `git revert`；`run_all` 回到 10 個 detector
- **持續成本**：每次數字變動要更新 `PROGRESS-METRICS.md` 的宣告值，否則 gate 紅。
  ⚠️ **這是刻意付的成本** —— 它正是「文件不會過期」的機制本身。

### ⛔ 射程限制（明寫以免被當成全覆蓋）

1. **五把尺是代理指標**，不是完成度。工具會自己印這句話，但讀的人仍可能忽略。
2. **里程碑判定仍是人的**。工具只保證「判定的前提還成立」，不保證判定本身對。
3. **分母是 Wave 1**。Wave 2/3、事件、供應商、AI agent 模組不在射程內。
4. **錨點只涵蓋能便宜驗證的里程碑**。M0（DoD 六項，含外部阻塞）與 M8（旗艦，前置是 P0 AD）
   ⛔ **沒有便宜的機械錨點** —— 這兩個的錨點欄位會明寫 `manual`，不假裝有。
